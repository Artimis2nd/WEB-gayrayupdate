1. 4 ส่วนที่ต้องแก้เสมอ

การ "เปลี่ยนอังกฤษเป็นไทย" บน SFC ไม่ได้มีแค่แก้ข้อความใน ROM แต่โดยทั่วไปต้องแก้ครบ 4 ส่วนนี้:

1. รูปแบบข้อมูลข้อความ

Encoding, ตารางตัวอักษร (.tbl), script และตัวชี้ข้อความ (pointer)

2. ระบบวาดข้อความ

ฟอนต์, tile, tilemap, VRAM และการจัดบรรทัด

3. ตรรกะภาษาไทย

สระบน/ล่าง วรรณยุกต์ และอักขระประกอบที่ต้องวาดเหลื่อมตำแหน่ง

4. พื้นที่ ROM / โค้ด

ย้ายข้อความที่ยาวขึ้น, ขยาย ROM, hook โค้ดเดิม, ทำ patch ที่แจกจ่ายได้

อย่าเริ่มจากแปลทั้งเกมทันที — ให้พิสูจน์ก่อนว่าแก้ "1 กล่องข้อความ" จนแสดงไทยได้ถูกต้องครบทั้ง 4 ส่วนด้านบน แล้วค่อยขยายไปทั้งเกม

2. เฟส 1 — สำรองและสำรวจ ROM

  • เก็บ ROM ต้นฉบับแบบอ่านอย่างเดียว และทำงานกับ "สำเนา" เท่านั้น
  • ตรวจชนิด mapping ของ ROM: LoROM / HiROM / ExHiROM, ขนาด ROM, มี header 512 ไบต์หรือไม่ และมีชิปพิเศษหรือเปล่า เช่น SA-1, Super FX
  • ทำ checksum/hash ของไฟล์ต้นฉบับ เพื่อให้ทุกคนในทีมใช้ ROM ฐานเดียวกัน
  • สร้าง Git repository เก็บโค้ด patch, ตารางอักษร, script, เอกสาร address และผลทดสอบ — ไม่เก็บ ROM ต้นฉบับ ในนั้น (ลิขสิทธิ์ + ขนาดไฟล์)

3. เฟส 2 — หา "เส้นทางข้อความ" ของเกม

เริ่มจากหน้าจอที่มีประโยคอังกฤษสั้นๆ และจำตำแหน่งข้อความนั้นไว้ ทำตามลำดับนี้:

  1. ค้นหา ASCII ใน ROM ก่อน เช่น START, SAVE, ชื่อเมนู หรือชื่อสถานที่
  2. ถ้าไม่เจอ แปลว่าเกมมักใช้ encoding เฉพาะ ให้ค้นหารูปแบบข้อมูลและสร้างไฟล์ตาราง .tbl
  3. ใช้ debugger ตั้ง read breakpoint ที่ตำแหน่ง RAM/ROM ที่เกี่ยวกับข้อความ หรือใช้ VRAM/tile viewer ดูว่าฟอนต์และ tilemap ถูกส่งขึ้นจออย่างไร
  4. เมื่อ breakpoint หยุด ให้ดู call stack และ trace ย้อนกลับเพื่อหา routine หลัก: อ่าน byte จาก script → แปลงรหัสเป็น glyph/tile → เขียน tilemap ลง buffer → DMA ข้อมูลเข้า VRAM
  5. จด address และหน้าที่ของ routine ทุกตัวเป็น "แผนที่ระบบข้อความ"

ผลลัพธ์ของเฟสนี้ควรเป็นแผนภาพเช่นนี้:

Script ใน ROM
  -> pointer table
  -> text decoder / control codes
  -> text buffer ใน WRAM
  -> glyph lookup
  -> tilemap buffer
  -> DMA ไป VRAM
  -> กล่องข้อความบนจอ

4. เฟส 3 — วิเคราะห์รูปแบบ Script และ Control Code

สิ่งที่ต้องหา:

รายการรายละเอียด
Terminatorbyte ที่จบข้อความ เช่น 00, FF
Control codesขึ้นบรรทัดใหม่, รอปุ่ม, เปลี่ยนชื่อคน, เปลี่ยนหน้า, แสดงตัวเลข
Pointer format16-bit, 24-bit, bank-relative หรือมีการบีบอัด
Compressionถ้าข้อความใน ROM ดูเป็นข้อมูลสุ่ม แต่รันไทม์เจอข้อความใน RAM อาจมีการคลายบีบอัดก่อนวาด
พื้นที่ว่าง (Freespace)ต้องหาอย่างระมัดระวัง และยืนยันว่าเกมไม่ใช้พื้นที่นั้นจริง
เริ่มด้วยการแก้คำอังกฤษสั้นๆ ให้เป็นคำอื่นที่มีจำนวนไบต์เท่ากัน เพื่อยืนยัน encoding และ pointer ก่อน แล้วจึงไปทำข้อความยาวหรือย้ายตำแหน่ง

5. เฟส 4 — ออกแบบระบบภาษาไทย

ภาษาไทยจะไม่จบแค่ "เพิ่ม glyph 1 byte ต่อ 1 ตัวอักษร" เพราะมีอักขระประกอบ (สระบน/ล่าง + วรรณยุกต์)

แนวทางเริ่มต้นที่แนะนำ: fixed-width + composite glyph

  • ใช้ glyph หลักเป็นตัวอักษรไทยมาตรฐาน
  • สร้าง glyph แยกสำหรับสระบน สระล่าง และวรรณยุกต์
  • แก้ routine วาดข้อความให้ glyph ประกอบถูกวาดที่ตำแหน่ง x/y offset เหนือตัวพยัญชนะก่อนหน้า
  • กำหนดกติกาสำหรับอักษรเช่น กิ่, ปุ้, น้ำ เพื่อเลี่ยงการชนกันของสระและวรรณยุกต์

ทำเป็น 2 ระยะจะปลอดภัยกว่า:

ระยะวิธีการข้อดี / ข้อเสีย
A — Prototypeฟอนต์ไทยแบบ glyph สำเร็จรูปสำหรับชุดที่ใช้จริง เช่น "ก่", "ก้", "กิ", "กี"เขียน engine น้อย แต่จำนวน tile สูง
B — Engineจัดวาง combining marks จริงตาม offsetรองรับภาษาไทยครบและประหยัด glyph กว่า แต่ต้อง reverse-engineer routine การวาดมากขึ้น

สำหรับเกมแรกหรือโครงการคนเดียว แนะนำเริ่ม ระยะ A เพื่อทำ prototype ก่อน แล้วค่อยตัดสินใจว่าจำเป็นต้องทำระยะ B หรือไม่

6. เฟส 5 — แก้ปัญหาข้อความยาวและการตัดบรรทัด

ภาษาไทยมักยาวกว่าข้อความอังกฤษ ต้องวางนโยบายตั้งแต่ต้น:

  • ปรับข้อความแปลให้กระชับ
  • เพิ่มจำนวนบรรทัดในกล่องข้อความ ถ้า UI รองรับ
  • ย้าย script ไปพื้นที่ใหม่และแก้ pointer
  • ทำ word wrap ตาม "ความกว้าง pixel/tile" ไม่ใช่จำนวนตัวอักษร
  • หากเกมใช้ฟอนต์ความกว้างแปรผัน (VWF) ต้องหา table ความกว้างตัวอักษรและเพิ่มค่าความกว้างของอักษรไทย
  • ถ้าเป็น fixed-width ให้กำหนดความกว้างทุกตัวเท่ากันก่อน เพื่อลดความซับซ้อน

7. เฟส 6 — เขียน Patch แบบทำซ้ำได้

อย่าแก้ ROM ด้วย hex editor อย่างเดียวในขั้นสุดท้าย เพราะตรวจสอบและแก้ย้อนยาก โครงสร้างโปรเจกต์ตัวอย่าง:

project/
  asm/
    main.asm
    text_engine.asm
    thai_renderer.asm
    hooks.asm
  data/
    font_th.bin
    text.tbl
    script_th/
  tools/
    build.py
  docs/
    memory_map.md
    text_format.md
  build/
    game_th.bps
  • เขียน hook และ routine ใหม่ด้วย 65C816 assembly
  • ใช้ assembler สร้าง patch ซ้ำได้
  • ทำ build script สำหรับ inject ฟอนต์, compile script และ apply ASM patch
  • แจกเป็น BPS/IPS patch แทนการแจก ROM เต็ม

Asar เหมาะกับงานนี้ เพราะออกแบบมาสำหรับ apply patch กับ ROM และรองรับ 65C816, SPC700, Super FX — github.com/RPGHacker/asar

8. เครื่องมือที่ควรมี

งานเครื่องมือแนะนำใช้ทำอะไร
Debugger หลักMesen-Sดู CPU register, memory, trace, breakpoint, assembler, Lua script และบันทึก ROM/IPS จากการแก้ไขได้ — mesen.ca
Debugger/ดูกราฟิกทางเลือกbsnes-plusมี debugger/disassembler และ viewer สำหรับ tile, tilemap, sprite, เสียง — bsnes.revenant1.net
Hex editorHxD หรือ ImHexดูและแก้ byte, ค้นหา text/pointer, เปรียบเทียบไฟล์
Assembly patcherAsarเขียน hook, inject routine ใหม่, จัดการ freespace และ build patch — คู่มือ Asar
Text/script toolsAtlas, Cartographer หรือ Python ที่เขียนเองdump script, insert ข้อความ, จัดการ table และ pointer
ฟอนต์/กราฟิกYY-CHR หรือ tile editor ที่รองรับ SNESวาด glyph ไทย, ตรวจ tile 2bpp/4bpp และ palette
Diff / ตรวจความเปลี่ยนแปลงVBinDiff, Gitเปรียบเทียบ ROM และติดตามโค้ด
สร้าง patch แจกจ่ายFloating IPS (FLIPS)สร้าง BPS patch และตรวจ ROM ฐาน
เอกสาร/โน้ต addressMarkdown + Gitบันทึก memory map, control code, pointer และข้อค้นพบ

Mesen-S มีทั้ง trace logger, memory tools, debugger และบันทึก ROM ที่แก้เป็น .sfc หรือ .ips ได้ จึงเหมาะเป็นเครื่องมือหลักช่วงค้นหา engine ส่วน bsnes-plus มี viewer ด้าน tile/tilemap โดยตรง มีประโยชน์มากตอนตามว่าข้อความถูกส่งเข้า VRAM อย่างไร

9. ลำดับการเรียนรู้ที่คุ้มที่สุด

  1. พื้นฐานเลขฐานสิบหก, endian และ pointer
  2. โครงสร้าง SNES: 65816, bank, WRAM, VRAM, DMA
  3. LoROM/HiROM address conversion
  4. 65C816 assembly ขั้นพื้นฐาน: LDA, STA, LDX, JSR/JSL, RTS/RTL, branch
  5. ระบบ tile, palette, tilemap ของ SNES
  6. breakpoint, trace และการอ่าน call stack
  7. text encoding, pointer table, compression
  8. ระบบจัดวางอักษรไทยและการวาด combining marks

10. Milestone ที่ควรกำหนด

Milestoneเป้าหมาย
M1เปลี่ยนคำอังกฤษ 1 คำโดยไม่ทำเกมค้าง
M2dump และ insert ข้อความ 1 กล่องได้
M3ฟอนต์ไทยขึ้นจอได้
M4แสดงพยัญชนะไทยได้ครบ
M5สระ/วรรณยุกต์ไม่ชนกันในประโยคทดสอบ
M6ข้อความยาวถูกย้าย pointer และตัดบรรทัดได้
M7เล่นตั้งแต่เริ่มจนจบเกมด้วย regression test
M8build patch จาก source ได้อัตโนมัติ และปล่อยเป็น BPS
ข้อสำคัญที่สุด: อย่าเริ่มเขียน engine ใหม่ก่อนที่จะรู้แน่ชัดว่าเกมเดิมอ่าน text, แปลง glyph และวาดลง VRAM ผ่าน routine ไหน การตาม data flow ของข้อความหนึ่งประโยคให้จบก่อน จะลดเวลาลองผิดลองถูกได้มากที่สุด
